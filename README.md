# SCOUT · 好戏开场

一个可以自行部署的 SCOUT 好友联机网页版。中文界面、电脑和手机浏览器可玩，采用原创的数字卡面；不包含实体游戏的原画素材。

## 已实现

- 2～5 人私人房间，6 位房间码、邀请链接、昵称。
- 3～5 人标准规则和 2 人专用规则。
- 开局整手旋转、锁定方向；相邻选牌、合法出牌提示。
- 招募两端卡牌、选择数字朝向和插入位置；每轮一次的招募＋出牌。
- 服务端洗牌、校验和计分，逐玩家发送状态，其他人的手牌不会发到你的浏览器。
- 自动结算、下一轮、最终排名与再来一场，同分共享胜利。
- 掉线重连、刷新恢复、房主离线转让、房主返回大厅、移除大厅离线座位。
- 每次成功操作原子写盘，重启后可用同一浏览器恢复原座位。
- Docker 部署、可选 Caddy 自动 HTTPS，另附 Nginx 配置示例。

## 游戏规则

以下说明对应本网页版当前实现。**一轮**指从发牌到本轮计分；**一场**包含多轮，最终比较累计总分。

### 1. 游戏目标与准备

通过出牌压过桌面组合、收取被压过的牌，以及让别人招募你的牌来得分。每轮结束时，剩余手牌通常会扣分。整场结束后总分最高者获胜，同分共享胜利。

| 人数 | 使用的牌 | 每轮每人手牌 | 整场轮数 |
| --- | --- | --- | --- |
| 2 人 | 44 张，移除上下数字为 9 和 10 的那一张牌 | 11 张 | 2 轮 |
| 3 人 | 36 张，移除所有含数字 10 的牌 | 12 张 | 3 轮 |
| 4 人 | 44 张，移除上下数字为 9 和 10 的那一张牌 | 11 张 | 4 轮 |
| 5 人 | 全部 45 张 | 9 张 | 5 轮 |

3～5 人每轮重新洗牌发牌。2 人首轮只发出 22 张，另外 22 张留给第二轮，不混回首轮用过的牌。第一轮由第一个座位先行动，此后每轮按座位顺序更换起始玩家。

### 2. 手牌方向与顺序

- 每张牌有两个数字，当前朝向的上方数字用于出牌，下方数字是旋转后的数字。
- 发牌后不能自行排序，也不能单独翻转已有手牌。可以选择将**整手牌旋转 180°**：每张牌的上下数字互换，整手牌的左右顺序也反转。
- 本网页版在确认前允许反复旋转查看；点击“确认这个方向”后锁定，所有人确认后开始行动。
- 开始行动后，已有手牌的相对顺序固定。出牌后两侧手牌自然靠拢；招募的新牌可以插入任意位置。

### 3. 合法组合与大小比较

出牌必须选择手中**位置连续、彼此相邻**的一段牌，且满足以下任一形式：

| 组合 | 示例 | 说明 |
| --- | --- | --- |
| 单张 | `7` | 任意一张牌 |
| 同数 | `4、4` 或 `6、6、6` | 所有数字相同 |
| 顺子 | `3、4、5` 或 `8、7、6` | 按手牌顺序逐张加 1 或减 1，至少两张 |

不能跳过中间的牌选取组合；`3、5、4` 不是顺子，`9、10、1` 也不能首尾相接。

比较大小时，按以下顺序判断，前一项分出大小后就不再比较下一项：

1. **张数优先：** 张数更多的合法组合更大。例如 `1、2、3` 可以压过 `9、9`。
2. **同张数比类型：** 同数大于顺子。例如 `2、2` 可以压过 `8、9`。
3. **同张数、同类型比数字：** 比较组合中的最小数字，较大者胜。例如 `4、5、6` 压过 `3、4、5`，`7、7` 压过 `6、6`。

必须**严格大于**桌面组合才能出牌；相同大小不能压过。桌面为空时，可出任意合法组合。

### 4. 3～5 人：每回合选择一个行动

玩家按座位顺序轮流行动，没有“跳过”选项。可以选择出牌、招募，或者使用本轮一次的“招募＋出牌”。即使能出牌，也可以选择招募。

#### 出牌（Show）

从手中打出相邻的合法组合，压过桌面组合：

- 将桌面原组合中**仍留在桌上的牌**全部收为得分牌，每张计 1 分；已经被招募走的牌不计入。
- 自己新打出的牌成为新的桌面组合，归自己所有；它们此时还不是自己的得分牌。
- 连续招募次数归零，轮到下一位玩家。若自己已经出完手牌，则立即结束本轮。

#### 招募（Scout）

从桌面组合的**最左端或最右端拿走一张牌**，不能取中间的牌，也不能招募自己的牌：

1. 选择拿左端还是右端；桌面只有一张时直接拿这一张。
2. 自由选择这张新牌使用哪个数字朝上。
3. 将它插入自己手牌的任意间隙，包括最左侧或最右侧；已有手牌不能借机重排。
4. 桌面组合的拥有者获得 1 枚招募得分筹码，价值 1 分，然后轮到下一位玩家。

桌面剩余组合继续有效，下一位玩家只需压过剩下的牌。若桌面被拿空且尚未触发本轮结束，下一位玩家可以自由出牌；桌面为空时不能招募。

#### 招募＋出牌（Scout & Show）

每位玩家每轮只能使用一次，在同一个回合内先招募一张，再立即出牌：

- 招募的取牌、朝向、插入位置和给原拥有者加 1 分的规则不变。
- 随后从招募后的手牌中选择相邻组合，压过**招募后剩下的桌面组合**；不必包含刚招募的牌。若桌面已空，可出任意合法组合。
- 成功后消耗本轮这次机会并结束自己的回合。若出牌不合法，整个操作都不生效，不会先拿走牌或消耗机会。
- 按完整行动判断是否结束本轮，不会在中间的招募步骤提前结算。该机会下一轮恢复，不累计。

### 5. 本轮结束与计分（3～5 人）

满足任一条件时，本轮立即结束：

- **有人出完手牌。** 所有人按实际剩余手牌扣分，出完者剩余为 0。
- **一次出牌之后，其余所有玩家连续只招募，没人出牌压过。** 也就是连续招募达到“人数减 1”次。最后一次出牌的玩家剩余手牌免扣分，其他人照常扣分。即使最后一次招募刚好拿空桌面，仍会按此规则结束。

每位玩家的本轮分数为：

```text
本轮得分 = 收到的得分牌张数 + 招募得分筹码数 − 剩余手牌张数
```

享有免扣资格时，最后一项按 0 计算。例如收到 4 张得分牌、获得 2 枚招募筹码、剩 3 张手牌，本轮得 `4 + 2 − 3 = 3` 分；若享有免扣资格，则得 6 分。本轮得分可以为负数。

结束时仍在桌面的牌不额外计入任何人的收牌得分。每轮分数加入累计总分；下一轮重新计算收牌和筹码。房主点击“开始下一轮”继续，完成全部轮次后比较累计总分。

### 6. 双人专用规则

双人沿用相邻选牌、组合比较、招募位置与朝向、出牌收牌和出完手牌结束的规则，以下差异替代多人规则：

- 每人每轮开始有 **3 枚招募筹码**。每次招募消耗自己的 1 枚筹码，桌面组合的拥有者不获得招募筹码。
- **招募后仍由自己行动**，可继续招募或出牌；成功出牌后才轮到对方。
- 没有“招募＋出牌”特殊行动，也不使用多人“连续招募人数减 1 次”的结束条件。
- 当前玩家既没有合法出牌、又已用完招募筹码时，本轮自动结束。最后出牌者的剩余手牌免扣分，对方按剩余手牌扣分。
- 本轮得分为 **收牌张数＋自己剩余的招募筹码数−剩余手牌张数**；免扣资格仍按上述规则计算。
- 共进行两轮，第二轮使用预留的 22 张牌，并换另一位玩家先行动。两轮累计总分更高者获胜，同分共享胜利。

### 7. 网页版怎么操作

1. 输入昵称创建房间，把“复制邀请链接”生成的链接或 6 位房间码发给朋友。复制被浏览器阻止时，可在弹出的窗口手动复制。
2. 2～5 人入座且全员在线后，由房主点击“开始游戏”。每人选择手牌方向并确认。
3. 轮到自己时，点一张牌可选单张；再点另一张牌，会选中两者之间的全部相邻牌，然后点击“出牌”。“提示可出组合”只帮助选牌，不会自动提交。
4. 点击“招募”选择端点、数字朝向和插入位置；点击“招募＋出牌”时，还需在预览手牌中选择要打出的组合，再一次性确认。
5. 房主可在开局后点击顶部“结束本局”，确认后**结束整场游戏，包括后续轮次**，清空本场手牌和分数，全员返回大厅；房间码与座位保留。无需轮到房主，也无需所有玩家在线。

断线或刷新后，用同一浏览器、同一访问地址重连可恢复身份与手牌。房主短暂断线有 30 秒重连宽限；持续离线且有其他在线玩家时，房主权限才会转交。已转交后，原房主重连不会抢回权限。大厅中主动离开的房主会立即转交权限。

游戏没有回合计时器，也不会替离线玩家自动行动。遇到长期离线玩家，房主可以结束本场回大厅，移除离线座位后重新开局。只有在大厅中才能离开房间或移除离线玩家。

规则参考：Oink Games 版本的 [规则说明书](https://www.hras.cz/user/related_files/new_edition_scout_rules_eng.pdf) 和 [规则文字版](https://www.rulespal.com/scout/rulebook)。本网页版的起始座位、方向预览、自动结算与房间管理行为以上述说明为准。

## 本地运行

需要 Node.js 24（也兼容 22.12 及以上）。

```bash
npm ci
npm run build
npm start
```

打开 `http://localhost:3000`。开发时使用 `npm run dev`，打开 `http://localhost:5173`，前端代理 API 和 Socket.IO 到 3000。

若 npm 官方源连接困难，可使用 `npm ci --registry=https://registry.npmmirror.com`。依赖完整性仍由锁文件的 integrity 校验。

**模拟多人：** 使用不同设备、不同浏览器配置或无痕窗口。一个浏览器下同一域名的多个标签页属于同一个人。手机可以访问电脑的局域网 IP；电脑防火墙需要允许对应端口。

## Ubuntu 24.04 部署

完整步骤见 [DEPLOY.md](DEPLOY.md)。已有 Docker 时：

```bash
sudo bash deploy/start.sh http
```

默认通过服务器的 8080 端口访问；有域名时可以使用 HTTPS 方案。

## 数据与架构

前端 React + Vite；后端 Node.js + Express + Socket.IO；规则模块在 `shared/rules.js` 和 `server/game.js`。

浏览器使用服务器生成的 HttpOnly、SameSite=Strict 会话 Cookie。持久化文件只保存会话令牌的 SHA-256 哈希。设置 HTTPS 的 `PUBLIC_ORIGIN` 后，Cookie 同时启用 Secure。

默认数据在 `data/rooms.json`；Docker 使用 `scout-table_scout-data` 命名卷。更新容器不会清空房间。全部离线且 24 小时无操作的房间会清理，属于好友临时牌桌，不是永久历史档案。清除浏览器 Cookie 或更换域名后，不能恢复原身份。

当前是**单 Node 进程、单副本**部署。不要同时启动多个进程写同一份数据文件，或在没有共享存储和 Socket.IO adapter 的情况下横向扩容。房间默认上限 200，是容量限制，不代表已经进行过 200 房间压力测试。备份与维护方法见部署文档。

## 环境变量

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PORT` | `3000` | Node 服务监听端口 |
| `HOST` | `0.0.0.0` | Node 监听地址 |
| `DATA_DIR` | `./data` | 房间持久化目录 |
| `PUBLIC_ORIGIN` | 空 | 生产来源校验，如 `https://scout.example.com`，末尾不加 `/` |
| `MAX_ROOMS` | `200` | 房间数量上限 |
| `HTTP_PORT` | `8080` | HTTP Compose 对外端口 |
| `BIND_ADDRESS` | `0.0.0.0` | HTTP Compose 对外绑定地址 |
| `DOMAIN` | 无 | HTTPS Compose 所用域名 |

Compose 自动读取根目录 `.env`。直接 Node 启动时可用 `node --env-file=.env server/index.js`，或者在系统环境中设置这些值。
